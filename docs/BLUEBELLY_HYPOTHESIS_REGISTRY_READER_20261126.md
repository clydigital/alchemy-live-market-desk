# Private hypothesis evidence reader

Read-side rollout of dynamic evidence gems. Existing Notion Research Gap Registry is the source; no new store, schedule, price requests, public admission or auto-attachment. One owner-authorized bounded query (8 most recently edited active/stale rows with stable Investigation IDs), then at most four first-block reads on Research Library only. Existing My Desk, Creator Intelligence and Power Stack research-impact shortcuts point to that single panel. Public Regime/Industry pages stay unchanged; use their independently qualified evidence pathways.

Optional structured projection: the first block of an existing registry page is a JSON code block with version "evidence-gems/1", hypothesisId (exact Investigation ID), reviewedOn (ISO date), currentRead (exact Current Read property), conditional (IF/AND/THEN/UNLESS), nextTest, gems (1–8; id, label, role, observation, sourceUrl HTTPS, sourceDate ISO or null, state, premise). Roles: CONFIRMS, WEAKENS, CONDITIONAL, AMPLIFIES, INVALIDATES, TRANSMITS, HORIZON_SHIFT. States: RETAINED_SOURCE_RECEIPT, ATTRIBUTED, PENDING. Retained receipt means previous research, not new verification. A matching currentRead is required; otherwise only the latest registry metadata and history link appear. Only update the designated block when a material reassessment is saved; keep historical narrative and original source receipts intact. Never interpret block availability as verified current data. No auto ranking or confidence percentages. Existing registry properties and source clocks continue to be authoritative. No schema changes.

Acceptance requires CI and authenticated readback of actual linked records; an anonymous redirect does not prove owner data is visible. Notion integration access may differ from the user's connected Notion tool. When unavailable show explicit status and registry link. No privacy loosening.
