# Bluebelly — Live Source Reasons and Manual Sweep Findings

This is a **read-only display layer**, not a new regime engine, cron job, or public verification claim.

## Automatic update

- All nine public Regime Watch lenses, the Regime Watch index, and Hormuz Watch read the existing durable X Wire posts and transcript-reviewed creator metadata on **each server-side page request**.
- The single server-side batch reader queries the existing \`x_wire_posts\` and \`research_intake_items\` ledgers. Each X lead is a monitored original post, within 48 hours; creator-video sources must be transcript-ready and reviewed, within 14 days. Post + review clock, source URL and reason must be visible.
- Each topic matches a short list of **research questions**; a matched source is **not** evidence that the stated mechanism occurred. Questions are derived deterministically, not generated by a new model or scheduled run. New stored posts/reviews appear on subsequent requests; there is no extra ingestion.
- Limit each topic to the existing bounded source lead count (three X posts plus two reviewed creator videos). The index reads once for all lenses.
- X excerpts remain public-post discovery, creator findings appear as safe categorical research questions plus the public video title; **never copy private creator claim-check text, raw transcripts or research notes to a public page**.
- These pages never write or revise the canonical Regime, Story, prices, earnings evidence or newsletter automatically. Exact original links and research checks let readers open the evidence.

## When a user asks for a manual research sweep

1. Research the named topic now. Prefer original/official documents, relevant market observation timestamps, then attributed X posts and actual reviewed transcript summaries as unverified opinions. Check each URL and event/retrieval date. Disclose contradictions and coverage gaps.
2. Prepare a precise, concise set of findings in the user's desired voice; include each reason, original source URL, timestamp, evidence status and next test. Do not invent information to fill the block.
3. Through the user's connected GitHub repository, edit **only** \`data/bluebelly-manual-sweeps.json\` to append the entry, on a feature branch. Preserve older entries and the \`version\` value. The pure projector validates it. Open a PR, run CI, then merge and verify the public readback. This is the deliberate authoring/approval step, not an additional scheduler or public write API.
4. After merge + Vercel production readiness, confirm the exact destination page displays the **YYYY-MM-DD — MANUAL SWEEP FINDINGS** block and cite the original sources. If deployment or source validation fails, do not say it is live.

### JSON entry format (illustrative only, **not** a finding)

\`\`\`json
{
  "version": 1,
  "sweeps": [
    {
      "id": "2026-11-10-ai-owner-sweep-1",
      "topic": "ai",
      "date": "2026-11-10",
      "researchAt": "2026-11-10T08:00:00Z",
      "title": "AI demand versus cash conversion — manual source check",
      "findings": [
        {
          "reason": "Describe only what the checked original source actually established.",
          "sourceName": "Publisher or issuer",
          "sourceUrl": "https://issuer.example.com/source",
          "sourcePublishedAt": "2026-11-10T07:00:00Z",
          "status": "RESEARCH_LEAD",
          "nextCheck": "Identify an independent source or priced consequence to validate."
        }
      ]
    }
  ]
}
\`\`\`

- Allowed topics: \`hormuz\`, \`fed\`, \`bonds\`, \`ai\`, \`china\`, \`energy\`, \`yen\`, \`breadth\`, \`gold\`, \`housing\`.
- Dates use **Malaysia's YYYY-MM-DD day**; full ISO timestamps include timezone. No future-dated findings.
- Allowed statuses: \`RESEARCH_LEAD\` (not independently confirmed), \`SOURCE_CORROBORATED\` (must carry an actual original/source link), \`CONTRADICTED\` (include contradictory dated source). No status changes the canonical Regime automatically.
- Publication is append-only history in Git, not an overwrite of a daily report. At most two most recent valid manual blocks per topic display at once; older entries stay available in repository history.
- The live source window and dated manual findings are deliberately distinct. An expired X post may disappear from current auto reasons while a sourced manual research note remains in the dated history.
