# Alchemy Skills v0.3 — Coding Integration Checklist

**Reference page:** [Notion Shared Contract](https://app.notion.com/p/3f7519b67a9481b1b426eab63732fbd3). This checklist describes the *next authorised implementation slices*; it does not mark them implemented.

## Stage 0 — installation and readiness (Skill side)

- [ ] Confirm which account/workspace supports custom Skill import; install only selected Skills, not all nine by default.
- [ ] In a fresh Alchemy conversation, prove one intentional source-router/measurement-audit invocation and a readable useful output.
- [ ] Verify plugin entitlements via one **source-specific read** each only when relevant. Do not require every provider to work before other tasks continue.

## Stage 1 — existing research schedules (only after Skill invocation is proven)

- [ ] Make a **small** amendment to the existing 2-hour MacroPulse task, not a replacement: optional Asia discovery using DayTrading.monster/Codex Market Skills and originals, conditional Acumen/Exa, US focus, Asia/Europe/US/Other candidate labels and no extra forced full post if no material change. Preserve exact Pulse ID, Log, Notion post-first verification, heartbeat, dedupe and chat output rules.
- [ ] Make bounded amendments to 08:10/20:10 Research Gap Gates: reuse existing full eligible pulses, route to source/measurement and material-gap work; OpenAlex only for a genuine scientific question; Pipeworx_BIS only for a specific supported source gap. Preserve Registry, window, case IDs, Notion write and concise final handoff.
- [ ] Retain the existing 06:00 16-company AI tracker; source FMP/FactIQ/issuer financials with matching periods and optional Public Equity Investing normalizer/earnings/thesis specialists.
- [ ] Preserve the fixed four creator universe and transcript-first evidence integrity; creator ideas are hypotheses, not accepted canonical Motion/Regime evidence.
- [ ] Compare one natural run before/after on source completeness, dedupe, useful analysis and token/plugin expenditure. One focused test per changed owner by default; expand only on a material failure.

## Stage 2 — Live / Hybrid regional News and Motion experience

- [ ] Read actual existing market-motion and Story schemas, the Regime operating framework and the canonical presentation adapter before choosing fields or migrations.
- [ ] Implement a read-only **Asia / Europe / US / Other** filter or region labelling in the existing presentation path first. Source origin and affected markets are separate. Avoid duplicating one Motion across regions.
- [ ] Show persistent Story connections, supporting and conflicting developments, why the reader follows the Story, what changed and next falsifier.
- [ ] Present Regimes as current market mindset with sensitivities to facts/price responses, conditional thesis-change triggers and uncertainty. No independent Story-version writer or acceptance route.
- [ ] Verify exact Dossier/Story/Motion identity and historical edition replay. If missing, give a clearly dated independent-news lane instead of fabricating acceptance.

## Stage 3 — plugin and key plumbing (only if actually needed)

- [ ] Check the **exact Vercel project + preview/production targets** for names/scopes of BEA_API_KEY, FRED_API_KEY, FMP_API, TALARION_API_KEY, OPENALEX_API_KEY. Never print key values.
- [ ] Identify existing backend adapters; a key in Vercel alone does not create one. Use one targeted request/fixture with original publisher, session/fiscal dates and source entitlement.
- [ ] Prefer original official/issuer sources before adding optional tool complexity. Pipeworx_BIS connected catalog scope may be narrower than generic advertised routing; inspect actual tool permissions.
- [ ] No key failures should halt independent market research; report the affected missing dimension.

## Stage 4 — quality-first editorial and MVP

- [ ] Manually invoke one full COTD from an actual supplied chart and one OB from real physical/economic originals. Use LY Style Guide + approved China/Brent example.
- [ ] Preserve an understandable, natural narrative, complete analysis, charts, FAQs if useful, dates and source links. No artificial shortening to satisfy MVP.
- [ ] Check factual preservation after at most one targeted optional Writer/Avoid AI Writing/No AI Slop pass. Render requested HTML/DOCX and inspect real layout.
- [ ] Test only relevant numeric/identity and output defects; do not force obscure hypothetical branches.

## Do not conflate these ownerships

- ChatGPT Notion Research Gap Gate ≠ production backend Research Gap.
- Provider discovery ≠ underlying original source ≠ canonical Evidence UUID.
- Research-only Market Motion ≠ promoted Motion with pinned evidence.
- System 1 provisional observation ≠ existing Dossier System 2 thesis acceptance.
- Existing frozen Hybrid presentation ≠ a new Regime reasoner.
- Manual OB/COTD publication ≠ scheduled Live/Dossier publication.

## Acceptance for each future code change

Record one owner, observed defect/request, exact existing source identifiers, minimal diff, narrow test, deploy target *if authorised*, exact readback and release status. A merged code PR or generated page timestamp alone never proves a live research observation or canonical Dossier change.
