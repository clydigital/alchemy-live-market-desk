# Calendar PRE-PRODUCTION — automatic refresh and evidence gates
**Adopted:** 21 October 2026 · **Owner:** existing Live Desk scheduled research intake
**Goal:** Replace implicit Finnhub-calendar dependence with an automated, evidence-labelled **pre-publication/pre-production acceptance step**. Keep the public Live, Blue and Hybrid calendars on their existing shared `getEconomicCalendar()` contract. Do not create a separate scheduler, Story writer, or provider-derived canonical release Evidence.

## Existing production ownership
The **existing Live research slots** at 09:30 and 21:30 Asia/Kuala_Lumpur run `lib/cron-research-handler.ts`. In that same authenticated slot, the calendar PRE-PRODUCTION stage now executes before the CPI-coverage evaluation and before publication. It does not move endpoints or authorise a new cron.

| State | Automatic action | Admission rule |
| --- | --- | --- |
| Upcoming (schedule) | Refresh live BLS ICS and the four official BLS release tables (CPI, PPI, Employment Situation, JOLTS), plus existing ISM official schedule and current dated central-bank/BEA backstops | Official publisher date/time/reference period only. An unconfirmed time remains unconfirmed. Never extrapolate a future date. |
| PRE-PRODUCTION (before release) | Existing official-actual ingestion seeds due official BLS `macro_releases` rows, without assigning actuals. PRE-PRODUCTION adds the four CPI metric-key placeholders with `consensus = NULL`. | Period, date and 08:30 ET schedule from official primary publisher. New schemas are not market measurements. |
| Expectations | If `TRADING_ECONOMICS_API_KEY` has access, request high-importance US calendar in the bounded future window; match agency release instant, exact reference month and CPI metric transformation | Only TE `Forecast` (survey consensus), **not** TE `TEForecast` (model projection). Only before the release timestamp; provider `Actual` must be absent and no post-release last update. Reject duplicate/ambiguous matches, wrong units and out-of-range values. |
| Immutable first pre-release receipt | Update only `macro_release_metrics` rows where both `consensus` and `consensus_captured_at` are NULL | Compare-and-swap, capture actual UTC collection time and source URI. Never backdate an after-release poll into a pre-release consensus. Existing post-release / late sources are left untouched. |
| After release | Existing `ingestOfficialMacroActuals` reads BLS official data-series Actuals and ISM official releases, updates actual/previous, and retries missing data | Do not replace a stored pre-release survey forecast. `Actual` and `Previous` are not a forecast. BEA/FOMC/ONS etc. still need source-specific actual adapters; their absent actuals remain gaps. |
| Validation | Same existing cron logs `scheduled_calendar_preproduction` with `READY/DEGRADED`, official count, missing forecast count, new captures and source-state warnings. Then run existing CPI evidence coverage check. | A missing optional vendor entitlement **degrades** calendar coverage; it does not block unrelated markets or fabricate forecast surprises. |
| Production presentation | Live/Blue/Hybrid still read the existing official schedule/Desk-record adapters | No Finnhub auto-polling, even if its API key is present. Issuer-confirmed earnings remain official; external earnings date estimates require independently approved/explicit opt-in. |

No fabricated survey consensus. |
| Reuters/LSEG poll, Bloomberg survey, Econoday | Survey expectations, often with multiple metrics and identifiable vintage | Forecast-vs-actual audit | Must establish legal commercial capture/access and exact pre-release timestamp; research article published afterwards cannot prove historical pre-release ingestion. |

**Important:** FRED/ALFRED vintages are useful for historical *official observations and revisions*, not automatically proof of a market survey's point-in-time forecast. The source's `published_at`, collection clock and release instant are distinct. Same-session financial price reactions still require independently timestamped market data.

## Runbook for maintaining the PRE-PRODUCTION calendar

1. **Source schedule:** The existing 09:30/21:30 MYT research cycle automatically polls official BLS schedules and ISM, combines them with official issuer dates and Desk rows, and safely retains existing dated backstops. New BLS table parsing preserves exact reference month and publisher ET time. The future release seed is inserted in `macro_releases` by existing official collector.
2. **Forecast intake:** PRE-PRODUCTION ensures metric placeholders for upcoming official CPI. If the licensed TE calendar API is available, map exact metric key (headline/core; m/m/y/y), reference month and same-date release instant; capture original `Forecast` at the current UTC time while `Actual` is NULL. The compare-and-swap never rewrites a previously captured source value or replaces BLS Actual.
3. **Acceptance:** Read the `scheduled_calendar_preproduction` log event attached to the current Live research slot. `READY` requires sources and no detected missing CPI forecast keys; `DEGRADED` states the precise missing upstream entitlement/forecast/official schedule. New actuals and downstream CPI source coverage are checked separately. Do **not** turn a missing survey into `met forecast`.
4. **After release:** Existing post-release official collector tries BLS / ISM in the same scheduled research cycle, retains `consensus_captured_at`, logs ingestion errors and rechecks; the calendar reads current release metrics. No extra cron needed. High-impact releases occurring between slots might be delayed until the next existing run; low-latency actuals would require a separately authorised event-window cadence.
5. **Provider changes:** Test any new source first with fixture: correct period/metric/unit, zero actual before release, true capture timestamp, no retroactive overwrite, complete source provenance, source-rights approval, and official Actual independent cross-check. Then add it under the **existing PRE-PRODUCTION source check**. Not every forecast/nowcast is survey consensus.
6. **Production promotion:** Test `tests/calendar-preproduction.test.ts` + full Validate Live Desk and database contracts. Check Vercel READY on exact merged SHA. Confirm scheduled `scheduled_calendar_preproduction` event and that `macro_release_metrics.consensus_captured_at < macro_releases.release_date` for any admitted forecasts. A successful build or a generic vendor calendar GET alone does not establish coverage.

## Known limitations and next checkpoints
- `TRADING_ECONOMICS_API_KEY` needs an **authorised commercial API entitlement** in the shared Vercel production environment. Until then the pipeline runs automatically but explicitly reports forecasts **DEGRADED** rather than inventing them. Do not expose this key to the client.
- BLS can rate-limit or block automated requests. iCal/backstops remain visible; if a reference period cannot be established, do not auto-seed a new month by guessing.
- The initial strict forecast mapper covers **four CPI transformations**. Expand PPI, payrolls, UK CPI, euro area flash HICP, PCE and GDP one metric family at a time with exact official units and sources, not a fuzzy event-name match.
- Exact 08:30 ET US releases can occur between the twice-daily research slots. This is a **scheduled pre-publication check, not a minute-level event release feed**. Live reaction trading needs a different, specifically authorised real-time collector.
- Historical late-captured TE/FMP values remain **unverified vintage** and cannot be relabelled pre-release. No 14 October CPI forecast has been backdated.
